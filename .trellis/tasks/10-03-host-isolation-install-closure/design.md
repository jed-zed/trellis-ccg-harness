# Installation closure design

## Coordinated gap closure, version 2

The control root is the new pinned Harness source, not a caller-selected trust anchor. Its immutable registry binds the reviewed known-owner declaration and the exact two original receipts. The old roots retain their original ownership entries and become archives for new controlled mutators; other claims are preserved, not transferred. Publication is registry first, both owner sidecars second, committed proof last. Pending, missing, tampered or partially published records never authorize stock takeover. Native Windows file/directory leases, exclusive no-clobber creation and shared transaction locks close mutation races. Recovery finishes only the exact approved metadata transaction.

Permanent retirement verification is separate from handoff preflight. The former verifies immutable authority and raw receipts after legitimate stock changes; the latter checks actual old package/tree/aliases, recipient pin, scoped continuity and read-only physical agent pins immediately before the independently receipted stock CAS. Neither stock rollback nor source recovery may resurrect old claims. Historic older programs do not understand this record; deployment uses the exact new entry and explicitly retires their management use without claiming an OS sandbox.

Astra's final commit is a combined source snapshot, not a personal CCG commit. Apply its separate CCG and Harness source patches only, preserve user non-instruction agent fields, and regenerate managed projections through the approved initializer. Publish a real CCG Git identity and import that exact tree. Worker lifecycle/ledger is an optional aid, not a provider permission boundary; small helpers do not require a formal team plan.

The hosts are separate installed products: personal `ccg-codex` from an exact clean personal source commit/tree, and stock Claude official CCG 3.6.7 plus an independent GPTPro addon. Trellis remains task authority. No provider/model/credential/permission change belongs to this migration.

`HomeDir` / `--home-dir` denotes AgentsHome. `CodexHome` / `--codex-home` denotes the physical Codex directory; the compatibility default is HomeDir/.codex. Bind both resolved roots into plans, digests, receipts, backups, subprocess environments and rollback. Reject path drift and link escapes; do not transplant roots.

Agent preservation requires an explicit validated plan for two known edits: additive `model` and `model_reasoning_effort` fields only. Keep original installed hashes/backups. Store separate preserved-user digests and verified baseline/current snapshots. Repeat installation verifies exact bytes and provenance. Uninstall/rollback retain user-owned bytes; prompts, sandbox, features and later changes never receive an ignore-drift exception.

Source promotion imports only the clean tracked personal CCG Git tree after quality checks. Component, package/commit/tree identity and runtime command change atomically. Namespace migration verifies old ownership before recording new ownership. No fabricated provenance or forced replacement of changed directories.

Claude installs pinned public tarballs and a sealed production-dependency cache using `--offline --ignore-scripts` into a private legacy prefix. The addon owns a stable absolute launcher, pins native Claude, and forwards argv with a fixed plugin directory. The reproduced PowerShell execution-policy rejection requires a native entry, not policy changes. New-session discovery uses no model/auth/Pro call.

All rehearsals use task-owned HOME/prefix/cache/project roots. Journal actual writes; verify repeat, failure recovery and user-edit-safe rollback. Daily installation remains separately pending after a complete executable contract.
