# Adapt GPT Pro bridge to current Codex browser

## Goal

Restore the GPT Pro bridge against the current Codex Desktop right-side in-app browser while preserving its existing fail-closed Windows UI Automation, exact-once submission, evidence-integrity, and exact-task continuation contracts.

## Requirements

- Keep Windows UI Automation as the only browser-control transport. Do not add coordinates, mouse synthesis, keyboard synthesis, clipboard use, screenshots/OCR, Playwright, Selenium, CDP, internal ChatGPT APIs, cookies, tokens, browser-profile access, or external-browser automation.
- Uniquely prove the Codex top-level window and the ChatGPT browser surface before reading or acting. The main Codex composer must never be accepted as the ChatGPT composer.
- Allow Codex to actively nominate or focus the intended Codex Desktop window before adapter execution, but treat that result only as a candidate hint. The adapter must independently enumerate and prove the window, ChatGPT surface, composer, canonical URL, auth state, and generation state before acting; ambient model browser state is never trust evidence.
- After the adapter first proves a window for an operation that may act, freeze that non-empty unique UIA RuntimeId into the existing command-scoped target binding before any repeated resolution, prompt preparation, filesystem persistence, or UI action. Every later resolution in that operation must match the frozen target; target loss, replacement, empty/duplicate RuntimeId, or identity drift fails closed and requires a fresh command rather than silent rebinding.
- Treat UIA RuntimeId as opaque and desktop/session-local. Do not parse its structure or reuse it as a cross-app-restart or cross-desktop persistent identity. After URL binding, persisted watcher state combines it with the exact conversation URL and current semantic capability proof; before that, only the strict acknowledged-fresh pending state may combine it with prompt/baseline/idempotency evidence.
- Treat the canonical exact `conversationUrlBound` as the durable conversation identity after it becomes available. A fresh send may start from the canonical ChatGPT root and, after one UI-acknowledged Invoke, temporarily remain bound only to its frozen `windowRuntimeId`, prompt hash, response baseline, and idempotency reservation while the exact URL is pending. That pending state may observe only the same window and may never navigate, rebind, resend, or complete evidence without later acquiring one exact URL.
- When a bound browser surface disappears, allow bounded automatic recovery before asking the user: reopen the Codex built-in browser surface, navigate only through a uniquely proved supported in-app UIA navigation action to the saved exact conversation URL, verify canonical URL equality plus login/security/Pro state and expected conversation evidence, then establish a new ephemeral RuntimeId. If the current app exposes no safe navigation action, stop for one manual recovery instead of using an external browser, synthesized input, default URL handler, CDP, or a guessed control.
- Limit automatic URL recovery to an already-running Codex Desktop instance. Never launch or relaunch the application for recovery.
- Make recovery and observation silent by default. They must not activate or switch the user's current Codex task/window, invoke a `codex://threads/...` deep link, bring Codex to the foreground, synthesize input, use the clipboard, or pull focus back after the user moves to another application or Codex window. A UIA recovery action is eligible only when the exact target window remains uniquely bound and a bounded live test proves that the specific supported pattern can run without foreground or focus change; otherwise persist a pending recovery and require one manual action.
- Keep composer input silent by default. When the Boss explicitly opts into foreground input, `send`/`run -AllowComposerFocus` may focus only the uniquely proved ChatGPT composer immediately before `ValuePattern.SetValue()`. It must still re-prove the exact prompt hash and one enabled Send control; it may not focus the address, synthesize input, or weaken exact-once/idempotency rules.
- URL acquisition in every command must use only the address value/text already exposed through UIA. The adapter must never call address `SetFocus()`, select address text, or restore focus to improve URL evidence; if a caller requires an exact URL and direct evidence is insufficient, it fails closed.
- If the original top-level Codex window disappears while another Codex window or task remains open, never repurpose, navigate, or mutate that other window. Automatic recovery may create a replacement built-in browser surface only through a uniquely proved in-app UIA action that is both target-isolated and background-safe; without that capability, fail closed while retaining the durable conversation URL for later recovery.
- Keep detached observation passive whenever the bound surface is readable. Before every recovery mutation, re-check the frozen target identity and sample the current focused top-level element; if that focus identity changes between proof and action, or the target identity/capability changes, defer without restoring focus or performing the action. A stable focus on another application or Codex task may coexist only with an independently live-proved focus-free action. The Stop Hook may continue only the exact registered Codex task and must not use Desktop Wake as a fallback.
- Use the Boss-selected pure-script root-wait continuation: start the existing detached UIA watcher with `-RootWait` and no Stop registration, then keep the same root turn active inside one blocking `wait-root` local script operation. The detached watcher remains the only UIA poller; the root wait reads only the exact state/event files and creates no subagent, model poll, scheduled turn, service, queue, prompt, submission, or network operation.
- Root-wait mode is an explicit continuation transport, not a hidden wake fallback. It records `codex-root-wait`, validates exact thread/watcher terminal metadata, requires Codex review, and forbids automatic resend. It cannot restore a browser UIA subtree hidden by switching tasks in the same top-level Codex window. Direct delegations record `codex-root-wait-reviewed` only after root review; CCG imports retain ownership of their existing import acknowledgement.
- Account continuity is an expected common case, not a trust bypass. A login/account/security barrier, inaccessible conversation, unexpected URL, or mismatched conversation evidence requires manual user action and must not silently create a new chat.
- Recovery from `send-intent` or `send-uncertain` is observational only: it may reopen the exact bound URL and resume response observation, but it must never invoke `send`, create a replacement conversation, reserve another idempotency key, or retry an uncertain submission.
- Preserve the existing legacy sidebar path when its independent ChatGPT document and address control are present.
- Support the current right-side in-app browser only if UIA exposes enough stable evidence to prove all of the following: the ChatGPT surface, exactly one eligible composer, Pro/login/security state, generation state, and a canonical `https://chatgpt.com` new-chat or exact conversation URL.
- A canonical ChatGPT root or GPT root is sufficient to start an explicit fresh send. Exact URL remains mandatory before final response evidence is completed and for every follow-up send. If an acknowledged fresh send does not expose the exact URL immediately, persist `sent` with pending URL binding and allow only same-window passive observation; malformed/changed URLs, uncertain acknowledgement, or any non-fresh unbound send still fail closed.
- Preserve one-shot `InvokePattern` actions, prompt-hash verification, durable per-user idempotency reservation, no automatic resend after uncertainty, bounded response isolation, evidence hashes, watcher registration, Stop Hook callback, and explicit continuation acknowledgement.
- Keep the watcher local and token-free. It must not click or write the main Codex composer and must not become a second orchestrator.
- Keep user interaction rules explicit: using other applications is allowed; interacting with the same Codex browser surface during `new-chat`, `send`, `wait`, or watcher observation may invalidate the binding and must fail closed rather than continue on a guessed target.
- Preserve unrelated dirty workspace state and the separately modified watcher files unless an implementation step proves a directly required overlap.
- Keep the discovered missing `$Script:Names.DesktopStop` property as a separate dormant `desktop-wake` defect. Do not repair it or make Desktop Wake part of the active Stop Hook/recovery path in this task.

## Acceptance Criteria

- [ ] Parser gates pass for the adapter, watcher, tests, and Stop Hook handler.
- [ ] Deterministic tests cover both legacy sidebar fixtures and current right-side browser fixtures, including unique surface/composer selection, rejection of the main Codex composer, ambiguity, missing URL, login/security barriers, generation state, and one-shot invoke/no-resend behavior.
- [ ] Deterministic tests prove safe Codex window discovery: explicit target, unique candidate, unique browser-bearing candidate, unique focused candidate, empty/duplicate RuntimeId rejection, top-level enumeration failure and `TopLevelWindowLimitExceeded`, and no first-record fallback.
- [ ] A target-loss regression proves that repeated `Resolve-LiveContext` calls during `send`, `new-chat`, acknowledgement, URL binding, and watcher observation cannot rebind to a different window after the operation target is frozen.
- [ ] URL-recovery tests separate durable conversation identity from ephemeral window identity: closing the bound browser surface discards the old RuntimeId, reopens only the exact canonical `conversationUrlBound`, re-proves the new surface, records a new RuntimeId, and resumes observation without resending.
- [ ] Recovery fails closed for missing/ambiguous navigation controls, login/security barriers, inaccessible or mismatched conversations, noncanonical URLs, and `send-uncertain`; prohibited fallbacks and duplicate submissions remain absent.
- [ ] Silent-recovery tests prove that a user working in another application or another Codex task keeps the same foreground/focused top-level element, receives no task/window switch, and has no main Codex composer, panel, tab, or URL mutated. Recovery either completes inside the still-bound background target with zero focus change or persists a pending/manual state.
- [x] Root, GPT-root, and exact-conversation URL reads make zero address `SetFocus`, text-selection, re-resolution-after-focus, or focus-restoration calls in every command.
- [x] New Chat retries only existing transient pre-action proof for three seconds against the same immutable target; hard barriers fail immediately, and New Chat Invoke remains outside the retry and occurs at most once.
- [x] Focus restoration is a no-op when the original top-level is the automation top-level; it is allowed only when automation temporarily owns focus that originally came from another top-level.
- [x] Composer writes make zero focus calls by default; explicit `-AllowComposerFocus` makes exactly one focus call on the uniquely proved ChatGPT composer before `ValuePattern.SetValue()` and leaves all pre-Send proof unchanged.
- [ ] When the original target window disappears, another open Codex window is never selected as a replacement even if it is the only browser-bearing or focused candidate. No `codex://threads/...`, app launch/relaunch, first-window fallback, or Desktop Wake is used.
- [ ] Deterministic tests cover passive background observation, safe deferral before focus-requiring UIA actions, user focus changing between proof and action, no focus restoration after that change, and exact-task Stop Hook delivery without Desktop Wake.
- [ ] Security regression tests continue to reject coordinates, synthesized input, clipboard, browser drivers/CDP, cookies, tokens, and browser-profile access.
- [ ] Existing watcher and Stop Hook tests pass, including replay-until-acknowledged, synthesized crash/timeout validation, and no desktop-composer wakeup.
- [x] Root-wait tests prove `start -RootWait` creates no Stop registration, records `codex-root-wait`, rejects transport changes on reused evidence, and allows root acknowledgement only for exact-thread/exact-watcher terminal evidence requiring Codex review with automatic resend disabled.
- [x] One bounded `wait-root` script blocks the active root on local files until the terminal event or its timeout, without a child agent, model-driven polling, UI mutation, network, response-text read, Stop claim, callback, or acknowledgement write; the root independently validates persisted evidence after return.
- [x] A harmless live `status` returns `ok=true`, `ready=true`, exactly one selected window and ChatGPT surface, exactly one ChatGPT composer, visible Pro state, no login/security barrier, `generating=false`, and a canonical allowed ChatGPT URL.
- [ ] A real end-to-end run succeeds in a new ChatGPT conversation: `new-chat` -> one `send -FreshConversation` -> `start -RootWait` -> terminal `wait-root` result `completed` -> non-empty isolated response with matching URL and hashes -> root-reviewed acknowledgement by the matching transport owner.
- [ ] Deterministic tests prove an acknowledged fresh root send can enter URL-pending `sent`, start RootWait on the frozen RuntimeId, adopt only the first exact URL exposed by that same window, and then complete normally; unacknowledged, uncertain, follow-up, changed-window, and changed-URL cases remain blocked with zero resend.
- [ ] The live run records the exact conversation URL, prompt/response/evidence SHA-256 values, timestamps, window runtime ID, watcher ID, Codex thread ID, terminal status, callback claim, and acknowledgement.
- [ ] If the current app still exposes no trustworthy UIA URL or browser surface, no prompt is sent, no exclusion/security boundary is relaxed, and the task is reported blocked with the exact missing capability. A fixture-only or partial result does not satisfy acceptance.
