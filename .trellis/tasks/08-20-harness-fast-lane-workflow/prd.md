# 规划 Harness 分级精简工作流

## 目标

让简单咨询、只读检查和已知局部范围的低风险小改默认走快车道；让重型任务只运行“必要骨架 + 被具体证据触发的门”，不再因为任务较重就默认开启全部产物、Provider、子代理和检查。风险或影响范围超过快车道条件时进入精简后的完整通道，但安全、数据、权限、外部状态和破坏性操作的真实硬门保持不变。

## 背景与已确认事实

- 当前 `.trellis/workflow.md` 要求无活动任务时，即使是 simple conversation / small task，也先询问是否创建 Trellis task；用户拒绝后才能跳过。
- 一旦创建轻量任务，现有流程仍包含规划、激活、实现、检查、spec 判断、提交确认和 finish/archive；完整收尾设计为 work、archive、journal 三阶段。
- `.codex/hooks/inject-workflow-state.py` 每轮从 `.trellis/workflow.md` 读取 `[workflow-state:*]` 块；请求分类的现有 Seam 已存在，不需要新建框架。
- 生命周期中的安全、Provider、发布、安装、同步和数据保护门仍有明确价值，本任务不削弱这些保护。
- 当前完整通道把复杂度、风险和流程体量绑定成固定套餐；重型任务常被迫生成重复产物、调用不必要的职责证据并扩大验证，形成耗时、重复权威和约束冲突。
- 根 `AGENTS.md` 和 `.harness/policies/collaboration-policy.md` 是受管投影；协作策略的可复用上游源是 `.agents/skills/harness-init/assets/collaboration-policy.md`。
- 当前权威工作区已有大量无关 dirty changes，其中 `.agents/skills/harness-init/assets/collaboration-policy.md` 已被修改；后续实施必须先核对并保护这些现有改动。

## 范围内

1. 在现有 Trellis 请求分类 Seam 中定义快车道与完整通道的判定规则。
2. 对满足快车道条件的请求，默认不询问是否创建 Trellis task，不创建任务产物，不进入 `task.py start`、finish/archive 或提交生命周期。
3. 快车道只执行完成请求所需的最小读取/修改和一个能证明结果的聚焦验证。
4. 明确完整通道升级条件，并保持现有安全、数据、权限、Provider、发布、安装、同步与破坏性操作保护不变。
5. 通过 Harness 的权威策略源和受支持投影机制保持项目策略一致，不直接手改受管投影。
6. 为分类行为和投影一致性增加最小、可运行的回归验证。
7. 把重型任务的完整通道拆成不可省略的最小骨架与按证据触发的可选门；任务“复杂”本身不能触发全部流程。
8. 每个额外产物、Provider、搜索、子代理、评审或扩大测试都必须能指出具体触发事实、预期输出和停止条件；没有触发事实时跳过。
9. 消除重复权威：同一要求或计划只保留一个 canonical artifact，其余层只引用或记录证据，不再复制完整规则。

## 范围外

- 修改或取消全局 Codex Polish 最终润色流程。
- 自动清理、完成或归档现有 14 个活动 Trellis 任务。
- 更换 CCG Provider 路由或权限继承；允许把原本无条件的规划 Provider、搜索、产品经理、子代理和质量门改为有证据触发，但不得绕过对应的联网/付费授权。
- 删除生命周期测试、完整离线门或信任边界检查。
- 新增框架、依赖、通用策略引擎、配置开关或未来扩展脚手架。
- 在本规划阶段实施、提交、同步、安装或调用外部 Provider。

## 约束

- Trellis 继续拥有任务身份、生命周期、需求、验收与完成状态；CCG 仅提供规划证据和质量门。
- 快车道判定必须 fail-closed：无法确认风险或影响范围时进入完整通道，不猜测、不静默降级。
- 不能用文件数或行数作为唯一安全判定；认证、权限、凭据、数据、外部状态等一票升级。
- 已存在的用户改动和未跟踪任务均受保护；实施计划必须包含冲突检测和可回退路径。
- 不改变 upstream-owned Provider behavior、fork-only extension 或 ADR-0001 的权限继承决策。
- 重型任务的最小骨架只保留任务身份与明确需求、一个权威计划、实际实现、适用验证和完成记录；其余步骤默认条件化，不以“稳妥”为由无条件加载。
- 不新增风险评分器、流程 DSL、第三套模式或配置矩阵；优先删减无条件规则并复用现有触发条件。

## 验收标准

- [ ] 简单咨询和纯只读低风险请求不再被要求先回答“是否创建 Trellis task”。
- [ ] 已知局部范围的低风险小改可以走“读取目标 → 最小修改 → 聚焦验证 → 汇报”，不产生 Trellis task、PRD、设计、归档或 journal。
- [ ] 认证/授权、凭据、数据迁移或丢失风险、Provider/联网/付费调用、发布、安装、同步、破坏性操作、多模块或共享核心影响仍进入完整通道。
- [ ] 模糊请求或无法证明低风险的请求进入完整通道，并在需要创建任务时保留明确用户许可。
- [ ] 快车道不得跳过适用于实际变更的输入校验、安全、数据保护、基本可访问性和聚焦验证。
- [ ] 受管协作策略从权威源通过支持的 Harness 初始化/更新路径投影，相关 owned snapshot 与根 `AGENTS.md` 块保持一致。
- [ ] 聚焦回归测试覆盖至少：简单咨询、只读检查、低风险局部小改、模糊请求和高风险升级；现有完整通道测试继续通过。
- [ ] 重型任务不再自动等同于全量流程；额外产物、Provider、搜索、子代理、评审和扩大测试只有命中明确触发条件时才执行。
- [ ] 完整通道仍保留一个权威需求/计划来源，其他层通过引用或证据标识承接，不复制第二份任务或计划权威。
- [ ] 每个被触发的额外门都有可核对的“触发事实 → 必需输出 → 停止条件”；没有事实时明确跳过，不能用未来可能性补足。
- [ ] 最终 diff 不包含 Codex Polish、任务债清理、Provider 行为或无关重构。

## 阻塞问题

- 新增的“重型任务精简”会改变已生成的 CCG 计划及职责分析输入；修订 CCG 计划前需按当前 Provider 边界重新取得一次只读 `backend=grok` 规划证据授权。
