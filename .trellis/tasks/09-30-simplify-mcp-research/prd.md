# 简化搜索调研：MCP 主检索与旧 ACP 入口保留

## 目标

让日常项目调研顺畅地发现类似项目、可复用开源实现、已有解决方案和适用论文。保留独立调研代理，以现有 grok-search MCP 为主要取资料工具，取消普通调研对旧 Grok CLI/ACP 及其证据门禁的依赖。

## 已确认需求

1. 鼓励积极搜索；主代理按独立问题拆分调研，使用现有 `web_search` 子代理，最后综合取舍。不增加新的研究角色。
2. `web_search` 保持 `gpt-6-luna / high`、只读和不派生子代理；不升级 Sol 或 max，不增加自动升级机制。
3. 日常只做必要核验：关键结论能对应原文；实际复用代码时查版本与许可证；采用论文结论时查实验条件；未核实内容明确标注。
4. 普通调研不自动启动 Grok CLI/ACP，不要求再并跑 Grok 证明 MCP 结果，不强制生成旧 manifest、哈希证据包，不等待旧搜索门禁或逐次申请豁免。
5. 旧自动入口及门禁指令注释保留，底层实现保留，便于将来明确要求时复用。它们不再是普通流程的默认步骤或失败兜底。
6. 现有 MCP 搜索的配置问题纳入整改，最终必须以真实搜索及原文读取验收，不能只证明 MCP 已安装。
7. Boss 在执行中补充：去掉本机 Trellis CLI 必须等于项目资产版本的强制门禁。已有 CLI 不因版本不同而降级或重装；保留可用性检查与源码来源校验。
8. Boss 后续要求 Grok MCP 默认使用最新模型；仅调整 MCP 模型设置，独立调研子代理仍保持 Luna/high。新接口已获准临时测试；默认模型已保存为经测试的 `grok-4.7-latest`，接口和密钥尚未持久切换。

## 范围与约束

- 规划阶段交付需求、设计、实施计划及必要调研记录；Boss 后续已明确执行本计划，允许在以下范围整改源码和个人配置。当前执行状态见 `execution.md`。
- 后续实现覆盖个人 CCG 的调用说明、GPT Pro 搜索前置条件、相关全局指令和现有配置；保持 Trellis 为唯一任务与计划权威。
- 不新增 MCP 客户端、Provider 类型、调研框架、证据格式、搜索审批、重试或自动降级系统。
- 不把旧 ACP 校验器改成接受未经观测的 MCP 证据，不伪造搜索成功或用户豁免。
- 不扩大为产品经理、GPT Pro 传输、代码质量、安全或其他非搜索流程的重构；正常代码改动验证仍按实际影响执行，不变成每次调研的门槛。
- 保留既有未提交修改；不直接手改受管源码快照或插件缓存。安装按受支持的来源同步流程进行；提交和推送不由执行指令隐含授权。

## 验收标准

- [x] 普通 CCG 规划、实现、审查、研究及 GPT Pro 入口不再主动调用旧搜索 route/ACP，或要求旧搜索证据作为前提；已有旧任务证据也不会让新普通调用恢复该要求。
- [x] 旧入口以明确的停用注释保留；实现、显式旧命令和相应严格校验可追溯，未经明确选择不调用。
- [ ] 主代理能按问题分派现有 `web_search`，子代理能使用已配置 MCP；模型仍为 `gpt-6-luna / high`。
- [x] 至少一次真实 MCP 搜索返回可打开的原始来源，能支持一条项目调研结论；若验收案例涉及代码复用或采用论文结论，补查对应版本、许可证或实验条件。
- [x] MCP 不可用时清楚报告缺失证据，不自动切回 Grok CLI、不伪造完成；不依赖该证据的本地工作可以继续。
- [x] 日常输出只包含有用发现、来源和必要的不确定说明，没有新增强制证据包或固定多轮核验。
- [x] 模板、插件说明和相关安装产物一致，定向回归及仓库要求的检查通过；原有无关修改保持不动。
