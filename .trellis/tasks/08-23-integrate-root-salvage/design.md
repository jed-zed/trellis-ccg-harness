# Design: main-first root evidence integration

## Boundaries

The dirty root worktree is an immutable source of historical evidence for this
task. All writes happen in a new worktree on `codex/integrate-root-salvage`.
The exact integration base is `ab9c2597054fbafb0353024a1593fea3798a7e8d`.

The integration branch uses a strict allowlist:

- `.trellis/tasks/**` for this integration task and selected historical task
  evidence;
- `.trellis/workspace/codex/**` only when generated by Trellis tooling;
- `CONTEXT.md` or `docs/**` only after confirming they are current,
  non-duplicated independent documentation.

All other root paths are denylisted. In particular,
`components/ccg-workflow/**`, `harness.sources.json`, `.harness/**`, provider
skills/scripts, runtime adapter code, tests, generated locks, and obsolete
specifications remain from `main` without manual merging.

## Backup Contract

The external backup stores two independent recovery channels:

1. Git recovery: branch bundle, 14-commit mbox, ordered commit inventory, and
   bundle restore verification.
2. Working-tree recovery: NUL-safe 124-path manifest, tar archive, tracked
   binary patch, source/restored SHA-256 manifests, status snapshots, and a
   top-level checksum manifest.

The restore exercise clones the bundle and extracts the dirty archive into a
temporary directory, compares commit IDs and file hashes, records the result,
then removes only that verified temporary directory.

## Salvage Decision Contract

Each candidate is classified as one of:

- include: current, independently useful evidence not already represented;
- merge minimally: valid content exists but overlaps a canonical main file;
- backup-only: historically valuable but superseded, duplicated, generated,
  user-owned, or tied to dead mechanisms.

No commit is cherry-picked wholesale. Conflicting Trellis journal/index files
are not copied; the current task is archived and `add_session.py` regenerates
the canonical workspace records.

## Verification

Before commit, compare all changed paths with `ab9c259` and fail if any path is
outside the allowlist. Independently compare the runtime/managed tree against
`ab9c259`, run Trellis validation, then execute the repository's complete
offline Harness and CCG gates. Recheck the root branch HEAD and dirty path set
after integration.

## Rollback

The root worktree never changes, so rollback is deleting neither evidence nor
history. If integration is invalid, abandon the new local branch/worktree and
recreate it from `ab9c259`; the external backup remains the recovery source.
